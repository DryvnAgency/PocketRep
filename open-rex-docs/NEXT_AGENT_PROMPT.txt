--------------------------------------------------------------------------------
CAVEMAN MODE — HARD RULES
--------------------------------------------------------------------------------

1. THREE WORD UPDATES.
   User-facing status while working = three words per update, max.
     "Staging files now."
     "Typecheck clean."
     "Zip rebuilt."
     "Committing now."
     "Pushed to main."
   Full sentences ONLY when you have a real question or a real blocker.

2. FIX ERRORS SILENTLY.
   Compile error, typecheck error, lint error, build error — fix and continue.
   Do NOT stop to explain. Do NOT ask if it's okay to fix. Fix, verify, move on.
   Only surface errors that:
     a) require a decision from the founder (e.g. which library to swap to),
     b) indicate a leaked credential or data loss,
     c) you have already tried to fix three times and failed.

3. SPLIT ON STREAM TIMEOUT.
   If you see "API Error: Stream idle timeout - partial response received"
   OR your response appears to cut off mid-sentence: split the current task
   in half and execute each half as a separate tool call / message.
   If the timeout happens AGAIN on a half: split into quarters.
   Do NOT keep trying the same size. Halve, quarter, commit.
   Rule of thumb: if a single file Write exceeds ~800 lines, pre-split it.

4. TIE THE HALVES TOGETHER.
   After splitting, always verify the pieces integrate. Typecheck the whole
   project, not just one half. Read imports to confirm they resolve.

5. EVERYTHING MUST COMPILE END-TO-END.
   Before the last "done" update, run:
     cd backend && npm run typecheck
     cd extension && npm run typecheck && npm run build
   If either fails, you aren't done. Fix silently (rule 2).

6. NEVER COMMIT SECRETS.
   No .env files, no tokens, no API keys, no Supabase service_role.
   If the founder pastes a PAT into the chat to let you push to
   DryvnAgency/OpenRex: use it once for the push, run the push, then tell
   them to revoke it immediately.

7. TWO REPOS. KNOW WHICH ONE YOU'RE IN.
   PocketRep (DryvnAgency/PocketRep) = historical monorepo. The open-rex/
     subfolder on branch claude/add-handover-docs-fL4XU was the staging
     area during the migration. Avoid editing there unless specifically
     backporting.
   OpenRex (DryvnAgency/OpenRex) = current standalone product repo. THIS
     is where new work goes.
   If your MCP scope is limited to one of them, say so. Do not pretend.

8. PUSHING TO OPENREX.
   Your MCP may or may not include DryvnAgency/OpenRex. If it does,
   push via your GitHub MCP tools. If not, the founder will hand you a
   fine-grained PAT with Contents: Read and write scoped only to
   DryvnAgency/OpenRex. Use the Git Tree API pattern in
   /tmp/push_openrex_update.py (see session log) — it's incremental via
   base_tree, fast-forward, no force. After push: remind them to revoke.

9. REX VOICE IS LOCKED. DO NOT EDIT.
   The prompt rules in shared/prompts.ts — Hey-only opener, banned phrases,
   one direct question, conversational consultant — are the product. Do
   not soften, relax, or tune the voice without the founder explicitly
   asking for it.

10. WHEN IN DOUBT, READ SESSION_LOG.txt.
    It has the full decision history. Don't re-litigate decisions that
    are already recorded there.
