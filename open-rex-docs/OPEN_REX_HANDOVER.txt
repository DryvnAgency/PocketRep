--------------------------------------------------------------------------------
WHAT OPEN REX IS
--------------------------------------------------------------------------------

A dealership customer-database reactivation SMS agent. One sentence:

  The rep opens their CRM in Chrome, clicks the Open Rex icon, and every
  dormant customer on the page gets a personalised Rex-voice check-in SMS
  drafted for them, queued for review in a dashboard, and sent via Twilio
  after the rep approves.

Separate product from PocketRep (mobile CRM), Rex Lens (Chrome extension
sales coach), and His Palabra (faith app). Four distinct repos; Open Rex's
canonical repo is DryvnAgency/OpenRex.

--------------------------------------------------------------------------------
FIRST-DAY CHECKLIST (you, the new human engineer)
--------------------------------------------------------------------------------

1. CLONE
   git clone https://github.com/DryvnAgency/OpenRex.git
   cd OpenRex

2. LOCAL ENV
   cp backend/.env.local.example backend/.env.local
   # edit backend/.env.local:
   #   NEXT_PUBLIC_SUPABASE_ANON_KEY  ← Supabase dashboard → Settings → API
   #   SUPABASE_SERVICE_ROLE_KEY      ← same page
   #   GEMINI_API_KEY                 ← https://aistudio.google.com/apikey
   # Leave Twilio fields blank until 10DLC approved.

3. SUPABASE SCHEMA
   Open the Supabase SQL editor for project fwvrauqdoevwmwwqlfav.
   Paste backend/supabase/schema.sql. Run. Idempotent — safe to re-run.

4. BACKEND
   cd backend
   npm install
   npm run dev         # http://localhost:3000
   curl http://localhost:3000/api/health
   # expect: { ok:true, env:{ supabase:true, gemini:true, ... } }

5. EXTENSION (pick one)
   A. Prebuilt zip:
      unzip extension/open-rex-extension-v0.1.0.zip -d /tmp/open-rex-ext
      Chrome → chrome://extensions → Developer Mode → Load unpacked
              → select /tmp/open-rex-ext
   B. Build from source:
      cd extension && npm install && npm run build
      Chrome → chrome://extensions → Load unpacked → select extension/

6. EXTENSION CONFIG (one-time, via SW console)
   Chrome → chrome://extensions → Open Rex → Service Worker → Inspect.
   In that DevTools console paste:
     await chrome.storage.local.set({
       backendUrl: 'http://localhost:3000',  // or https://open-rex.vercel.app
       dealerId: 'your-dealer-id',
       authSecret: '<must match DASHBOARD_AUTH_SECRET in backend env>',
     });

7. SMOKE TEST
   Open a VinSolutions worklist tab. Click the Open Rex icon.
   Badge should show "Nd" (N = drafts generated).
   Open http://localhost:3000/drafts → the draft workspace should list
   N cards with visibly different openers. Each card shows the
   customer's vehicle, phone, and selected outreach angle.

--------------------------------------------------------------------------------
RISKS YOU SHOULD KNOW ABOUT
--------------------------------------------------------------------------------

- CRM UI changes break scraping. VinSolutions tenants render differently.
  The list-view grid IDs are VinConnect-specific; the profile parser uses
  broad label regex. Expect to patch selectors quarterly at worst.
- Carrier spam filtering on high-volume 10DLC traffic. The angle-rotation
  + opener-fingerprint system was built specifically to lower the risk,
  but nothing's verified at real volume yet.
- Gemini free-tier limits (15 RPM / ~1M tokens/day). Fine for pilot
  volume. When you outgrow it, either upgrade Gemini or swap to Claude
  Haiku 4.5 in backend/src/lib/gemini.ts — generateText signature stays
  the same (see OPEN_REX_MASTER_CONTEXT.txt "LLM provider" section).
- Supabase service_role leaks. Never commit it. The dashboard uses the
  service role directly because RLS is intentionally permissive today;
  post-MVP migrate to Supabase Auth with proper row policies.
