before touching any code.

## WHAT THIS IS

Open Rex is a dealership customer-database reactivation agent. It scrapes the
dealer's CRM customer profiles via a Chrome extension, generates personalized,
compliance-aware SMS messages (not blast-y template voice), drips 100-200
texts/day to the existing customer base to prompt upgrades, trade-ins, and
resales, runs the back-and-forth reply conversation with each lead until an
appointment is set, then texts the owner "appointment scheduled: name +
number" so the owner enters it into their CRM manually.

One-liner disambiguator:
  Rex Lens coaches the rep live on their screen.
  Open Rex reactivates the dealer's dormant customer base via personalized SMS
  drips with no rep in the loop.

## WHO IT'S FOR

Dealership owner-operators and sales managers running used-car and new-car
stores who have a customer list sitting in the CRM and no systematic
reactivation motion. Primary launch market: same PocketRep base — automotive
dealers on VinSolutions and similar CRMs.

## WHY IT EXISTS

Every dealership has thousands of past customers sitting in the CRM that nobody
calls. Generic "we have great specials!" blasts get filtered by carriers and
ignored by recipients. Reps don't have time to write personal texts to each
one. Open Rex sends varied, human-feeling texts so each recipient sees
something that reads like a real salesperson wrote it specifically for them,
not a template going out to a thousand people.

## END-TO-END WORKFLOW

1. Owner opens the dealer CRM in Chrome → clicks Open Rex "campaign mode" in
   the extension.
2. Extension walks the CRM's customer list and profile pages, extracts data
   (name, phone, last purchase, vehicle, last contact, consent flag) → posts
   to backend.
3. Backend (Gemini) drafts a personalized SMS per customer, varying phrasing
   ("ha" vs "hi", contractions, word order), context-aware on time of month,
   time of year, and upcoming holidays.
4. Owner reviews drafts in the dealer web dashboard → approves or edits →
   campaign queued.
5. Always-on backend scheduler sends 100-200/day via Twilio 10DLC, respecting
   quiet hours and STOP/HELP keywords.
6. Inbound replies hit the Twilio webhook → Gemini conversation agent replies
   until appointment intent is detected or the lead says "keep me in mind."
7. On appointment intent: backend texts the owner's phone "Appointment
   scheduled: <name> <phone> <time>" → owner enters it into the CRM manually.
   No CRM write-back.

## AI PERSONALITY — "REX"

Carry the 30 Rex persona rules from Rex Lens VERBATIM. Same voice, same
persona, same guardrails. Open Rex speaks in the same Rex voice.

Open Rex-specific additions for SMS voice:

- Vary salutations per message — rotate: ha, hey, hiya, morning, howdy
- Use contractions freely, occasional lowercase starts, casual rhythm
- Vary sentence structure — never start two consecutive messages the same way
- Context rotate on timeframe: beginning/middle/end of month, season, upcoming
  holiday — reference naturally, never cheesy
- One ask per message max
- Reference the customer's actual vehicle by name ("your Silverado")
- Never use blast giveaway language — banned phrases include: "huge sale",
  "limited time offer", "act now", "don't miss out", "biggest event", "crazy
  deals"  [TODO: expand banned list]
- Must pass the "does this read like a real salesperson wrote it just for this
  person?" sniff test

## KNOWN ISSUES / RISKS

1. CRM UI changes will break the scrape. Plan for an adapter-per-CRM pattern
   with a fast fix-forward loop.
2. 10DLC brand + campaign approval takes 2-6 weeks per dealership. Onboarding
   flow needs to handle pending-approval state gracefully.
3. Gemini drafts occasionally violate the banned-word list. Always run a
   post-generation filter before queueing.
4. Appointment-intent detection false positives — lead says "maybe next year"
   and agent flags it as appointment. Require structured time extraction, not
   just intent classification.
5. Twilio carrier filtering on high-volume patterns. Rotate phrasing, respect
   caps, monitor delivery rates per carrier.
6. TCPA liability is real. Consent must be provable per recipient.
