    Open Rex borrows its scraper pattern and persona file.

WAVE 3 — SECURITY FIX: SUPABASE ENV INJECTION (PR #10)
================================================================================

Trigger: founder reported Vercel had a security incident; any secrets sitting
in Vercel env vars should be treated as compromised. Scan turned up two real
problems in the monorepo:

  1. RexLens/src/shared/supabase.ts hardcoded the Supabase URL and anon JWT
     as string constants. Anon keys are public-by-design (Chrome extension
     bundles them), but rotating them was a code change.
  2. Pocketrep/thankyou.html (marketing site) embedded the same URL + anon
     key in inline JavaScript.

Fix shipped as PR #10 on branch claude/secure-supabase-env-injection
(off main, independent of Open Rex PR #8):

  - RexLens: esbuild.config.mjs now reads RexLens/.env at build time and
    injects SUPABASE_URL + SUPABASE_ANON_KEY via esbuild's `define`.
    supabase.ts reads process.env.SUPABASE_URL / ANON_KEY. Tiny inline
    dotenv parser (no dotenv dep).
  - Pocketrep: thankyou.html now uses __SUPABASE_URL__ and
    __SUPABASE_ANON_KEY__ placeholders. scripts/build-pocketrep.mjs
    copies Pocketrep/ -> dist/ and substitutes from Vercel env vars at
    build time. vercel.json switched to buildCommand + outputDirectory=dist.
  - Root .gitignore added to exclude dist/, .env*, node_modules/.
  - PocketRepApp (Expo) hardcoded URL fallbacks stripped; env refs only.
  - snack-HeyRexOrb.js left inline with a comment (Expo Snack has no env
    mechanism).

Verified: grep across the repo confirms no remaining hardcoded JWT or
project-ref. RexLens + Pocketrep both build cleanly with test env values.

Founder action after merge: rotate Supabase anon + service_role, rotate
Gemini key, rotate Twilio tokens, revoke Vercel personal tokens, uninstall
and reinstall the Vercel <-> GitHub integration, update env vars in Vercel.
Documented end-to-end in the PR body.

  /tmp/push_openrex_update.py

    - Preserves files outside the changed set via base_tree dedup.

WAVE 6 — EXTENSION INJECT-ON-DEMAND FIX
================================================================================

Founder reported: clicking the extension icon threw "Could not establish
connection. Receiving end does not exist." Classic Chrome error — manifest-
declared content_scripts inject on page load only; if the tab was opened
BEFORE the extension install/reload, or the tab is on a host the manifest
doesn't match, sendMessage has no listener on the other end.

Fix in extension/src/background/service-worker.ts (commit ee28418,
comment-tightening follow-up 7e8d670):

  1. Validate tab hostname against CRM_PATTERNS (vinsolutions / tekion /
     cdk / dealersocket). Unsupported host throws UnsupportedHostError
     which paints the badge "N/A" in grey instead of red "ERR".
  2. chrome.scripting.executeScript({ target: { tabId }, files:
     ['dist/content-script.js'] }) immediately before sendMessage.
     Wrapped in try/catch so already-injected cases don't crash — the
     ensuing sendMessage will surface any real error.
  3. 100ms delay after executeScript so the onMessage listener has a
     tick to register before sendMessage fires.
  4. Badge color: purple on success, grey on empty/N-A, red on ERR.

Content script: window.__openRexLoaded sentinel so a second injection
is a no-op (avoids duplicate onMessage listeners).

Extension zip open-rex-extension-v0.1.0.zip rebuilt. Founder loads the
packaged zip (vs building from source) and still gets the fix.

WAVE 7 — PROFILE-LEVEL SCAN + ANGLE-ROTATED MASS OUTREACH
================================================================================

Founder's big ask after the UI redesign: "Work like the Claude Extension
except prompted to scan customer profiles, read the notes, come up with
an outreach text based off the history, trade in vehicle, vehicle
purchased, time frame since last contacted. Just find a way to get in
the door and start communicating with the customer. Whenever I decide
to do a mass text based off the current list of customers on the page
then you will adjust the message and be different every text message
to not be the exact same to avoid being flagged."

Two requirements interlocked:

  A. Rex-Lens-style rich scan — read the full profile page, not just
     the list view.
  B. Per-customer bespoke SMS that differs from every other SMS in the
     batch, to avoid carrier spam filtering.

Shipped as commit ca387e2 on PocketRep PR #8 (10 files, +2765 line
growth mostly from new package-lock):

SHARED TYPES (shared/types.ts)
  ScrapedCustomer grew with 6 rich fields: notes, interactionHistory,
  tradeInVehicle, purchasedVehicle, purchaseDate, lastContactDate.
  Added OutreachAngle type with six members.

SHARED PROMPTS (shared/prompts.ts)
  OUTREACH_ANGLES: map from angle -> one-sentence coaching directive.
    check_in       plain "how's the vehicle treating you"
    mileage_prompt acknowledge time gap
    service_frame  upcoming service / season frame
    lease_aware    only if lease context present
    time_lapse     years since purchase if purchase date known
    neighbor_check peer-reference "catching up with folks from around then"
  buildMassOutreachPrompt(customer, angle): full rich-profile context +
  one angle directive. System prompt = CORE_VOICE_RULES +
  MASS_OUTREACH_FRAME + angleDirective.
  openerFingerprint(body): first 6 words, lowercased, alphanumeric
  only — used for in-batch duplicate detection.

SUPABASE MIGRATION (backend/supabase/schema.sql)
  Appended at bottom:
    alter table customers add column if not exists notes text;
    alter table customers add column if not exists interaction_history text;
    alter table customers add column if not exists trade_in_vehicle text;
    alter table customers add column if not exists purchased_vehicle text;
    alter table customers add column if not exists purchase_date text;
    alter table customers add column if not exists last_contact_date text;
    alter table drafts add column if not exists angle text;
  Idempotent. Founder runs once in the Supabase SQL editor.

BACKEND DRAFT GENERATOR (backend/src/lib/draft-generator.ts)
  New generateMassOutreachDrafts(customerIds[]) that:
    - Fetches all rows in one Supabase call.
    - Round-robins across OUTREACH_ANGLES by index (i % 6).
    - Calls Gemini at temperature 0.85 (bumped from 0.7) for more
      phrasing variance.
    - Runs the existing validateDraft regen loop (max 3 attempts).
    - Second pass: any two drafts sharing the same openerFingerprint
      trigger a regen of the later one under the next angle.
    - Bulk-inserts drafts with the angle column set.
  generateFirstOutreachDraft kept as a thin wrapper for back-compat.
  generateReplyDraft unchanged.

BACKEND API (backend/src/app/api/scrape/route.ts, .../drafts/route.ts)
  /api/scrape now accepts the six rich fields in each customer row and
  returns customerIds in the response so the extension can chain
  directly into draft generation.
  /api/drafts routes to generateMassOutreachDrafts.

EXTENSION (extension/src/adapters/vinsolutions.ts)
  extractProfileFromHtml now pulls:
    - notes via sectionAfterHeading matching /notes|comments/i
    - interactionHistory via extractActivityHistory scanning tables
      with date/type headers
    - tradeInVehicle, purchasedVehicle, purchaseDate, lastContactDate
      via valueForLabel (td/dt/th label-then-value pattern)
  All fields optional; missing ones return null and don't break the
  scrape. Heuristics will need per-tenant tuning on first real run —
  documented at the top of the extractor.

EXTENSION (extension/src/background/service-worker.ts)
  runScrapeFlow now chains scrapeTab -> uploadScrape (returns IDs) ->
  generateDrafts(customerIds) in one icon click. Badge reads "Nd"
  (N = drafts queued) on success.

Typecheck clean extension + backend. Build clean. Zip rebuilt (7.4 KB).
