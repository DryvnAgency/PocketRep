1. PRODUCT OVERVIEW
================================================================================

Open Rex is a dealership customer-database reactivation SMS agent. It sits on
the dealer's dormant customer list — people who bought or leased a vehicle and
haven't been contacted in a long time — and sends personalised, Rex-voice
check-in SMS to reopen the conversation. When a customer replies, Rex runs
the thread until it detects appointment intent, then pages the dealer's rep.

Sibling to (but distinct from) PocketRep (React Native CRM for reps), Rex Lens
(Chrome extension sales coach), and His Palabra (faith-based app). Four
products, four repos. Open Rex's canonical repo is DryvnAgency/OpenRex.

Audience: dealership owner-operators and sales managers. Same customer base as
PocketRep. Targets automotive retail first; SMS approach generalises.

4. DATA MODEL (Supabase)
================================================================================

Every table has RLS enabled but policies are permissive today — the
service_role key (used by the backend) bypasses RLS, and the dashboard
authenticates via a shared bearer secret. Migrate to Supabase Auth +
per-dealer policies post-MVP.

dealers
  id uuid pk
  name text
  crm_platform text
  created_at timestamptz

customers
  id uuid pk
  dealer_id text
  platform text  (vinsolutions / tekion / cdk / dealersocket)
  external_id text
  first_name, last_name, phone (E.164), email
  vehicle (primary vehicle label from list view)
  last_contacted_at text
  status, source, raw_context text
  notes text                    ← rich profile, from detail-page parse
  interaction_history text      ← rich profile
  trade_in_vehicle text         ← rich profile
  purchased_vehicle text        ← rich profile
  purchase_date text            ← rich profile

  unique (dealer_id, external_id)

  id uuid pk
  customer_id uuid fk → customers(id) on delete cascade

5. AI SYSTEM
================================================================================

LLM provider — LOCKED DECISION:
  Gemini 2.5 Flash on Google AI Studio free tier (~15 RPM, ~1M tokens/day).
  Sized for dealer-pilot volume. Swap path to Claude Haiku 4.5 documented
  below.

Why not Claude Max:
  - Max covers claude.com + Claude Code only. The Anthropic API
    (sk-ant-…) is separately billed regardless of Max.
  - Anthropic Consumer Terms forbid OAuth tokens from Pro/Max in external
    products. Agent SDK requires a Gemini-or-Anthropic API key.

Swap path (when/if):
  - ONE file: backend/src/lib/gemini.ts
  - Replace @google/generative-ai with @anthropic-ai/sdk
  - Model: claude-haiku-4-5-20251001
  - Env var: GEMINI_API_KEY → ANTHROPIC_API_KEY
  - generateText({system, user, temperature, maxOutputTokens, images})
    signature stays the same. Map ImagePart[] to Anthropic's
    content blocks. draft-generator.ts does not change.
  - Cost at current pricing: Haiku 4.5 ~$0.00025 / 200-token SMS vs
    Gemini Flash paid ~$0.00047.

Trigger to swap: recurring free-tier 429s, or draft-quality bump needed.

Three prompt flows:

  A) FIRST OUTREACH (single draft, legacy wrapper)
     buildFirstOutreachPrompt(customer) — thin wrapper that now routes
     through generateMassOutreachDrafts([customerId]) for consistency.

  B) MASS OUTREACH (primary flow)
     buildMassOutreachPrompt(customer, angle) — full rich profile +
     one angle directive. Used by generateMassOutreachDrafts.
     Six angles, round-robin across a batch by index:
       check_in, mileage_prompt, service_frame, lease_aware,
       time_lapse, neighbor_check.
     Temperature 0.85 (vs 0.7 elsewhere) for phrasing variance.
     After generation, openerFingerprint() (first 6 words lowercased,
     alpha-num only) flags any dupes; dupe's later draft regenerates
     under the next angle in the rotation.

  C) REGENERATE FROM NOTES (per-draft)
     buildRegenerateFromNotesPrompt(firstName, vehicle, repNotes,
       hasImage) — composer panel in the dashboard. Rep types notes +
     optionally uploads an image (screenshot, vehicle photo, handwritten).
     POST /api/drafts/[id]/regenerate → Gemini multimodal call with
     ImagePart[] → replaces the draft body.

  D) REPLY LOOP (inbound Twilio webhook)
     buildReplyPrompt(conversation) — full thread history + customer.
     Output includes optional APPOINTMENT_SIGNAL sentinel; backend
     strips it and inserts appointment_signals row + texts the dealer's
     DEALER_ALERT_PHONE.

Validation (shared):
  validateDraft(body) enforces:
    - must open with "Hey"
    - no banned phrases (20+ patterns: huge sale, limited time offer,
      act now, don't miss out, biggest event, crazy deals, … and all
      hyphen/dash variants)
    - max 320 chars
  generateWithValidation loops up to 3 attempts, feeding violations
  back into the user prompt.

Rex voice, verbatim from shared/prompts.ts:
  - Open every message with "Hey <FirstName>,". Only canonical opener.
  - Conversational consultant, not a closer. Frame = "how can I help
    you?" not "time to upgrade."
  - One direct question per message, about the customer + vehicle, not
    about a sale.
  - Never pitch upgrade/trade in message one. Trade emerges from reply.
  - Reference the customer's actual vehicle by name.
  - Never use dashes of any kind (-, --, —, –).
  - 2–3 sentences max.
  - Time awareness: end of month, beginning of month, mid-month,
    holidays — referenced naturally or not at all.


6. SURFACE ARCHITECTURE
================================================================================

  1) Chrome extension — one-click mass outreach
     User clicks icon (or Ctrl+Shift+O) on a CRM worklist.
     SW: validate host (CRM_PATTERNS) → executeScript inject on demand
         → 100ms settle → sendMessage {type: 'open-rex:scrape'}
     Content script: pickAdapter() → adapter.prepare() → adapter.extract()
         → returns rich ScrapedCustomer[]
     SW: uploadScrape → backend returns customerIds
     SW: generateDrafts(customerIds) → backend runs mass generator
     Badge: "Nd" success, "0" empty list, "N/A" unsupported host, "ERR"
            other failures.

  2) Dealer dashboard — review, approve, send
     /                  Home stat grid
     /customers         Customer table
     /drafts            3-column workspace
                        - list: pending drafts with active highlight
                        - thread: draft bubble + composer with Rewrite-
                          from-notes panel
                        - detail: customer card (name/phone/email/
                          vehicle of interest/last contact/tags)
     /appointments      Unacknowledged signal feed (pink glow) +
                        acknowledged (faded)
     /settings          Env health (Set/Missing per key)

  3) Backend agent — passive, Twilio-driven
     /api/twilio/webhook verifies X-Twilio-Signature, looks up customer
     by phone, inserts inbound message, generates reply via Gemini,
     detects appointment signal, optionally texts dealer.

  4) Dealer SMS alert — DEALER_ALERT_PHONE env var, triggered on
     appointment signal with format:
       "Open Rex: appointment signal from customer <id>. Check the
        dashboard."


7. COMPLIANCE
================================================================================

TCPA: prior express written consent required before any outbound SMS to
a consumer. Open Rex assumes the dealer has captured this during the
original sale — this must be verified per dealer at onboarding.

10DLC A2P registration: required for any application-initiated SMS at
volume. Brand + campaign registration, 2–6 weeks. Until approved, leave
TWILIO_MESSAGING_SERVICE_SID blank — the backend will refuse to send.

Quiet hours: not enforced yet. Spec is 8a–9p local to the recipient's
area code. Add at scheduler time — see TODO list.

STOP / HELP / START: not automated yet. Twilio handles STOP at the
carrier level for registered campaigns, but Open Rex should persist
the opt-out to compliance_events for dealer record-keeping. Add before
first real production cohort.

Banned phrases: enforced in-prompt + validated post-generation. Current
list includes huge sale, limited time offer, act now, don't miss out,
biggest event, crazy deals, special promotion, lowest prices,
unbeatable, amazing offer, exclusive deal, incredible savings, once-in-
a-lifetime, flash sale, blowout, clearance event, plus hyphen/dash
characters that would mark the message as blast-authored.

Daily send cap: not enforced in code yet. Spec is 100–200/day per
number.

9. KNOWN ISSUES & RISKS
================================================================================

 - CRM UI drift. VinSolutions tenants render differently. Selectors in
   extension/src/adapters/vinsolutions.ts are broad but will need per-
   tenant tuning. Plan: keep selectors in data constants at the top of
   the adapter file for fast iteration.

 - Carrier filtering on 10DLC. The angle-rotation + opener-fingerprint
   system lowers the risk but hasn't been tested at real batch volume.
   First large send should be paced and monitored.

 - Gemini free-tier ceilings (15 RPM / ~1M tokens/day). Fine for pilot.
   Swap path to Claude Haiku 4.5 documented in section 5 above.

 - Phone format mismatch between scrape and inbound. Scraper normalises
   to E.164 +1NNN…; Twilio inbound From is also E.164. Verify once
   real SMS flows.

 - Dashboard auth is a shared bearer secret. Swap to Supabase Auth +
   proper RLS policies post-MVP.
