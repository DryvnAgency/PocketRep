## PRODUCT

**Name:** PocketRep (PocketRep.pro)
**Tagline:** "The rep's edge, not the store's"
**What it is:** AI-powered sales follow-up coach + CRM-lite for individual sales reps
**Who it's for:** Individual sales reps (auto, mortgage, real estate, HVAC, roofing, fence, D2D, insurance, solar, B2B, staffing). Reps pay themselves — NOT dealerships/managers.
**The pitch:** Rex (AI coach named after a real-world top closer archetype) reads the rep's book, scores who's hot, writes the follow-ups, handles objections, and reviews the rep's week.

**Three product surfaces:**
1. **PocketRep Mobile App** (Expo / React Native) — iOS + Android + Web. Rep's book, heat sheet, deals, sequences, Rex chat.
2. **Rex Lens** (Chrome extension) — reads CRM screens (VinSolutions, Gmail, Outlook, generic pages) and generates outreach scripts. Works on any web page.
3. **Pocketrep landing site** (static HTML on Vercel) — pocketrep.pro — marketing, pricing, privacy/terms, thankyou page.

## DESIGN / BUSINESS DECISIONS THAT MATTER

1. **Server-side AI caps, not client-side.** Daily limits live in the edge function. Do NOT trust client-enforced caps.
2. **Single-rep product.** Do NOT add team/manager features. That's dealership product — different buyer, different price, different code.
3. **Gemini-only for text.** Do NOT re-add Anthropic Claude without pricing analysis. Gemini 2.5 Flash is ~10x cheaper and good enough at this quality tier. Keep the `/anthropic` route deprecated (returns 410).
4. **Rex tone**: closer energy, no em-dashes, no bullet points in generated scripts, "hey" not "hi", never say "trade value" (say "potential equity").
5. **Heat scoring is client-side** in `app/(tabs)/index.tsx`. The DB fields `heat_tier`, `heat_score`, `heat_reason` exist but are computed fresh on every load. Do NOT refactor this to a server job without reason — it keeps the app offline-resilient.
6. **Pro vs Elite differentiator is rex_memory** (summaries) + weekly digest + 100-item batch size (vs 50). Keep that gate clear.
7. **Rex Lens auth is shared with mobile app** via Supabase session persistence. Users log in once.
8. **Privacy policy explicitly names Google + OpenAI** — if you change providers, update privacy.html same PR.
9. **Landing site is hand-written HTML**, not a framework. Resist the urge to migrate to Next. It's fast + zero build cost.
10. **Picovoice is the only reason Hey Rex works on native**. If PICOVOICE_KEY is missing, the orb gracefully degrades with a console warning.

## KNOWN BUGS / ISSUES SPOTTED WHILE READING CODE

1. **`rex.tsx` has a stale alert message** referencing `ANTHROPIC_KEY` in error text (line 337 in the error branch of `send()`: "Connection error. Check your network and API key."). Minor — user-facing string. The actual ANTHROPIC_KEY env var is gone. Error message should probably just say "Connection error. Check your network."
2. **Deep Review "30s timeout" log is wrong** — `AI_TIMEOUT_MS = 60_000` but `err.name === 'AbortError'` throws "AI request timed out (30s)". Off-by-one in the message.
3. **`parseRexAction` throws silently** on malformed JSON inside `<action>` tags and returns null. Ok behavior, but there's no telemetry — we won't know how often Rex emits bad JSON.
4. **`exportBook` CSV escape is partial** — only escapes `notes` field (`.replace(/"/g, '""')`). If a contact's name or email contained commas/quotes, the CSV would be malformed. Low risk, worth hardening.
5. **`contacts.tsx` lazy-requires `expo-contacts`** — if the package isn't installed in a build, syncing from phone contacts silently fails. Low risk but we should add a UI state to surface "contact sync unavailable in this build".
6. **`HeyRex.tsx` PICOVOICE_KEY fallback is silent** — the orb just doesn't wake. Should show a toast or banner to the rep so they know to configure.
7. **`ai-proxy/index.ts` doesn't stream** — it blocks on full Gemini response before returning. For long prompts (Deep Review game plan with 30 leads + 3000 tokens), client may timeout. Consider SSE streaming later.
8. **The `/anthropic` deprecated route triggers an internal 410 but bypasses rate limit increment** — intentional, but if someone builds against the old URL, usage caps won't apply. Ok for now since it just errors them out.
